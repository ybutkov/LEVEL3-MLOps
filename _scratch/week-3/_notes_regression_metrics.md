# Регрессионные метрики (regression metrics)

> Конспект для week-3 baseline. Цель — понимать, что считаем, почему именно это, и где метрика начинает врать.

## 1. Базовый объект — ошибка (error / residual)

Для одного наблюдения:

```
e_i = y_i - ŷ_i
```

где `y_i` — истинное значение (true / actual / observed), `ŷ_i` — предсказание (prediction / fitted value). Сами по себе `e_i` (их называют **остатками / residuals**) бесполезны как метрика: сумма с разными знаками сократится. Метрика — это способ агрегировать вектор остатков в одно число.

## 2. MAE — Mean Absolute Error (средняя абсолютная ошибка)

```
MAE = (1/n) * Σ |y_i - ŷ_i|
```

**Что говорит:** «в среднем модель ошибается на X единиц целевой переменной».

**Свойства:**
- Единицы измерения совпадают с таргетом (interpretable). Для bike-rental: «в среднем модель промахивается на 5 аренд в час».
- Все ошибки взвешены **линейно** (linearly weighted) — ошибка 10 вдвое хуже ошибки 5.
- Робастна к выбросам (robust to outliers) — большая ошибка не «накачивает» метрику квадратом.
- Минимизируется **медианой** (median), а не средним: если в каждом сегменте предсказать медианный таргет, MAE будет минимален.

**Когда выбирать:**
- Хочешь интерпретируемое число в единицах таргета.
- Распределение остатков имеет тяжёлый хвост (heavy-tailed) или есть выбросы, которые ты не хочешь, чтобы доминировали метрику.
- Все ошибки «одинаково плохи».

## 3. MSE и RMSE — Mean Squared Error / Root Mean Squared Error

```
MSE  = (1/n) * Σ (y_i - ŷ_i)²
RMSE = √MSE
```

**Что говорит RMSE:** «в среднем модель ошибается на X единиц таргета, но крупные ошибки взвешены сильнее».

**Свойства:**
- RMSE возвращает единицы таргета (через `√`). MSE даёт квадратные единицы — менее интерпретируемо, поэтому MSE чаще как loss для оптимизации, RMSE для отчётности.
- Квадратичная (quadratic) штрафная функция: ошибка 10 даёт штраф 100, ошибка 5 — штраф 25. То есть один промах на 10 хуже, чем два промаха по 5 (вместе 50 vs одно 100). **RMSE наказывает большие ошибки непропорционально.**
- Минимизируется **средним** (mean) — если предсказать среднее в каждом сегменте, MSE/RMSE минимальны.
- Не робастна к выбросам — один большой промах поднимает метрику заметно.
- Дифференцируема всюду → удобна как loss-функция для градиентных методов (linear regression, neural nets).

**Когда выбирать:**
- Большие промахи дороже маленьких по сути задачи (например: предсказание спроса, где большой недопрогноз = большие потери).
- Целевая функция модели и так MSE (LinearRegression, многие XGBoost-режимы) — тогда RMSE на eval аналогична по «природе».

**Соотношение MAE и RMSE:**
- Всегда `RMSE ≥ MAE`.
- `RMSE / MAE ≈ 1` — ошибки однородные.
- `RMSE / MAE >> 1` — есть «толстый хвост»: модель в большинстве случаев точна, но иногда катастрофически промахивается. Полезный диагностический сигнал.

## 4. MAPE — Mean Absolute Percentage Error (средняя абсолютная процентная ошибка)

```
MAPE = (100/n) * Σ |y_i - ŷ_i| / |y_i|
```

**Что говорит:** «в среднем модель ошибается на X% от истинного значения».

**Свойства (и почему опасно):**
- Безразмерна → можно сравнивать между задачами с разными таргетами.
- **Не определена при `y_i = 0`** — деление на ноль. У нас bike-rental с полным гридом → много нулей в `total_rentals` для тихих kiosk-часов. **MAPE использовать нельзя.**
- Даже когда нет нулей: **асимметрична**. Промах вверх и промах вниз дают разные проценты. Завышение спроса в 2 раза (50 → 100) даёт MAPE=100%, занижение в 2 раза (100 → 50) даёт MAPE=50%. Модель, минимизирующая MAPE, систематически **занижает** предсказания.
- Завышенно реагирует на малые `y_i`: ошибка на 1 при `y=2` это 50%; та же ошибка на 1 при `y=100` это 1%. Если у тебя смесь маленьких и больших таргетов, MAPE доминируется поведением на маленьких.

**Альтернативы для безразмерной метрики:**
- **sMAPE (symmetric MAPE)** — симметричный вариант, но тоже плох при нулях.
- **WAPE (Weighted Absolute Percentage Error)** = `Σ|e_i| / Σ|y_i|` — устойчив к нулям, не доминируется малыми таргетами. Часто лучший выбор для retail/demand forecasting.

**Bike-rental:** MAPE отметаем сразу из-за нулей. Если нужна безразмерность для отчётности — WAPE.

## 5. R² — Coefficient of Determination (коэффициент детерминации)

```
R² = 1 - SS_res / SS_tot

SS_res = Σ (y_i - ŷ_i)²       — sum of squared residuals
SS_tot = Σ (y_i - ȳ)²          — total sum of squares, относительно среднего ȳ
```

**Что говорит:** «доля дисперсии таргета (variance), которую модель объясняет, сверх того, что объясняет константное предсказание средним».

**Интерпретация значений:**
- `R² = 1` — идеально, все остатки нулевые.
- `R² = 0` — модель не лучше, чем предсказывать средним всегда (baseline = mean predictor).
- `R² < 0` — модель **хуже**, чем предсказывать средним. Бывает на test, если модель переобучилась.
- `R² ≈ 0.7` — модель объясняет 70% вариативности таргета.

**Важные нюансы:**
- R² — это **относительная** метрика. Она ничего не говорит о размере ошибок в реальных единицах. Высокий R² на «лёгкой» задаче и низкий R² на «трудной» задаче могут означать одинаковую полезность модели.
- На train R² монотонно растёт при добавлении любых фич (даже шумовых). Поэтому есть **adjusted R²**, который штрафует за число фич, но в ML обычно используем train/test split, а не adjusted R².
- Чувствителен к выбросам так же, как RMSE (тоже квадраты).
- При очень разнородном таргете (часть сегментов с большой дисперсией, часть с малой) глобальный R² усредняет — может выглядеть хорошо, но в части сегментов работать плохо.

## 6. Сравнительная таблица

## 7. Для bike-rental — что брать

**Основной набор для отчётности:**
- **MAE** — интерпретируемое число для бизнеса («модель в среднем промахивается на N аренд в час на kiosk»).
- **RMSE** — для оптимизации и для отслеживания крупных промахов.
- **R²** — для понимания, насколько модель в принципе ловит сигнал поверх mean baseline.

**Отношение `RMSE / MAE`** — диагностическая проверка: если оно >> 1, у модели проблемы с outlier-часами (пиковые часы пятницы 17:00 vs ночные нули).

**MAPE / sMAPE — нельзя**, у нас нули в таргете.

**Отдельно держим в голове:**
- Считать метрики **в разрезах**: по `hour_of_day`, по `location_id`, по `month`. Глобальная MAE = 5, но если на пиковые часы MAE = 50 — модель не годится для планирования.
- При сравнении моделей: разница в MAE 5.2 vs 5.0 — это 4% улучшения. Это много или мало? Зависит от практической ценности. Не зацикливаться на третьем знаке.

## 8. Loss vs metric (важный концептуальный шов)

- **Loss function** (функция потерь) — то, что модель минимизирует во время обучения. Это про математику оптимизации, должна быть дифференцируема.
- **Metric / evaluation metric** — то, по чему ты *оцениваешь* модель. Может не быть дифференцируемой.

Они могут не совпадать. Пример: обучаешь XGBoost с loss=`squared_error` (≈ MSE), а оцениваешь по MAE. Это нормально, но имей в виду: модель оптимизирует не то, что ты замеряешь. Иногда стоит совместить — `loss='absolute_error'` если действительно хочешь оптимизировать MAE.

## 9. sklearn API

```python
from sklearn.metrics import (
    mean_absolute_error,        # MAE
    mean_squared_error,         # MSE (squared=True по умолчанию)
    root_mean_squared_error,    # RMSE (sklearn >= 1.4)
    r2_score,                   # R²
    mean_absolute_percentage_error,  # MAPE — осторожно с нулями
)

mae  = mean_absolute_error(y_test, y_pred)
rmse = root_mean_squared_error(y_test, y_pred)
r2   = r2_score(y_test, y_pred)
```

В версиях sklearn < 1.4: `mean_squared_error(..., squared=False)` для RMSE.

Для cross-validation все эти метрики доступны как scorer strings: `"neg_mean_absolute_error"`, `"neg_root_mean_squared_error"`, `"r2"`. Префикс `neg_` потому, что sklearn максимизирует score, а MAE/RMSE надо минимизировать → берётся отрицательная.
